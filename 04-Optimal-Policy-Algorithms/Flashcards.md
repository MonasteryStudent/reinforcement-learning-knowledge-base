## Card 04-001

**Front**

What is dynamic programming in the context of Markov decision processes?

**Back**

Dynamic programming refers to a collection of methods that solve a Markov decision process by using Bellman updates and reusing previously calculated value estimates.

These methods require the system model, including the reward probabilities and state-transition probabilities, to be known.

## Card 04-002

**Front**

What is generalized policy iteration?

**Back**

Generalized policy iteration is the general idea of letting value estimation and policy improvement interact.

It is not a specific algorithm. Many reinforcement-learning algorithms follow this idea by repeatedly updating value estimates and using them to improve the policy.

## Card 04-003

**Front**

What is value iteration?

**Back**

Value iteration is a dynamic-programming algorithm that repeatedly applies the Bellman optimality update to approximate the optimal state values.

A greedy policy is obtained by selecting an action with the greatest estimated action value in every state.

## Card 04-004

**Front**

Write the state-value update used by value iteration.

**Back**

First calculate the estimated action values:

$$q_k(s,a)=r(s,a)+\gamma\sum_{s'\in\mathcal{S}}p(s'\mid s,a)v_k(s').$$

Then select the greatest action value:

$$v_{k+1}(s)=\max_{a\in\mathcal{A}(s)}q_k(s,a).$$

## Card 04-005

**Front**

How does value iteration obtain a greedy deterministic policy?

**Back**

For every state $s$, the policy selects an action whose estimated action value is maximal:

$$q_k(s,\pi_{k+1}(s))=\max_{a\in\mathcal{A}(s)}q_k(s,a).$$

If several actions share the maximum, any one of them can be selected.

## Card 04-006

**Front**

Why is value iteration guaranteed to converge to the optimal state values?

**Back**

The Bellman optimality operator is a contraction when $\gamma\in(0,1)$.

According to the contraction mapping theorem, repeatedly applying this operator converges to its unique fixed point, which is the optimal state-value vector $\mathbf{v}^*$.

## Card 04-007

**Front**

Are the intermediate values produced by value iteration necessarily state values of a policy?

**Back**

No.

An intermediate value vector $\mathbf{v}_k$ is only an estimate generated by the Bellman optimality updates. It is not guaranteed to satisfy the Bellman equation of any policy.

Only after convergence does it approach the optimal state-value vector $\mathbf{v}^*$.

## Card 04-008

**Front**

What is a synchronous value-iteration update, and when can the iteration stop?

**Back**

During one iteration, every new state value is calculated using only the old value vector $\mathbf{v}_k$. Newly calculated values are not used until all states have been updated.

A practical stopping condition is

$$\left\|\mathbf{v}_{k+1}-\mathbf{v}_k\right\|_\infty\leq\varepsilon,$$

where the infinity norm is the greatest absolute change among all state values.

## Card 04-009

**Front**

What is policy iteration?

**Back**

Policy iteration is a dynamic-programming algorithm that repeatedly alternates between two steps:

1. Policy evaluation calculates the state values of the current policy.
2. Policy improvement constructs a greedy policy from those values.

The process continues until policy improvement no longer changes the policy.

**Tags**

04-Value-Iteration-Policy-Iteration

## Card 04-010

**Front**

What happens during the policy-evaluation step of policy iteration?

**Back**

The current policy $\pi_k$ is kept fixed, and its state values are calculated by solving its Bellman equation:

$$\mathbf{v}_{\pi_k}=\mathbf{r}_{\pi_k}+\gamma\mathbf{P}_{\pi_k}\mathbf{v}_{\pi_k}.$$

The equation can be solved directly or by applying iterative Bellman updates until convergence.

**Tags**

04-Value-Iteration-Policy-Iteration

## Card 04-011

**Front**

What happens during the policy-improvement step of policy iteration?

**Back**

The action values are calculated using the state values of the current policy:

$$q_{\pi_k}(s,a)=r(s,a)+\gamma\sum_{s'\in\mathcal{S}}p(s'\mid s,a)v_{\pi_k}(s').$$

The improved policy selects an action with the greatest action value in every state.

**Tags**

04-Value-Iteration-Policy-Iteration

## Card 04-012

**Front**

Why does greedy policy improvement produce a policy that is at least as good as the current policy?

**Back**

The current state value is the policy-weighted mean of the available action values. The greatest action value cannot be smaller than this mean.

Therefore, selecting a greedy action in every state produces a policy $\pi_{k+1}$ satisfying

$$v_{\pi_{k+1}}(s)\geq v_{\pi_k}(s)$$

for every state $s$.

## Card 04-013

**Front**

Why can policy iteration stop when policy improvement does not change the policy?

**Back**

If policy evaluation is exact and the improved policy is identical to the current policy, the current policy already selects an action with the greatest action value in every state.

Its state values therefore satisfy the Bellman optimality equation, so the policy is optimal.

## Card 04-014

**Front**

Are the value vectors produced after the policy-evaluation steps of policy iteration true state-value vectors?

**Back**

Yes, provided that each policy is evaluated completely.

Each resulting vector $\mathbf{v}_{\pi_k}$ solves the Bellman equation of policy $\pi_k$ and therefore contains the true state values of that policy.

## Card 04-015

**Front**

What is truncated policy iteration?

**Back**

Truncated policy iteration is a variant of policy iteration that performs only a finite number of iterative policy-evaluation updates before improving the policy.

The current policy is therefore improved using approximate rather than exact state values.

## Card 04-016

**Front**

Write the truncated policy-evaluation update.

**Back**

Starting from an initial estimate $\mathbf{v}^{(0)}$, the current policy $\pi_k$ remains fixed while the following update is performed:

$$\mathbf{v}^{(j+1)}=\mathbf{r}_{\pi_k}+\gamma\mathbf{P}_{\pi_k}\mathbf{v}^{(j)}.$$

The update is executed only for a fixed number of steps instead of continuing until convergence.

04-Value-Iteration-Policy-Iteration

## Card 04-017

**Front**

What steps are performed during truncated policy iteration?

**Back**

Each outer iteration performs the following steps:

1. Keep the current policy fixed.
2. Perform a finite number of policy-evaluation updates.
3. Calculate action values from the resulting approximate values.
4. Construct a greedy deterministic policy.
5. Repeat until the value estimates and policy are stable.

**Tags**

04-Value-Iteration-Policy-Iteration

## Card 04-018

**Front**

Are the intermediate values generated by truncated policy iteration true state values?

**Back**

Generally, no.

Because policy evaluation is stopped after a finite number of updates, the resulting values are only approximations of the state values of the current policy.

They become exact state values only if policy evaluation is continued until convergence.

## Card 04-019

**Front**

How are value iteration and policy iteration special cases of truncated policy iteration?

**Back**

The algorithms differ in the number of updates performed during policy evaluation:

- Value iteration corresponds to performing one evaluation update before improving the policy.
- Truncated policy iteration performs a finite number of evaluation updates.
- Policy iteration continues policy evaluation until the state values have converged.

Thus, truncated policy iteration provides a connection between the other two algorithms.

## Card 04-020

**Front**

How many policy-evaluation updates should truncated policy iteration perform?

**Back**

Zhao's general guideline is to perform a few evaluation updates, but not too many.

A few updates can improve the value estimates and reduce the number of outer iterations. Performing too many updates increases the evaluation effort and may provide little additional improvement before the policy is updated again.
